# Linap2 - Промт описания проекта для диаграмм прецедентов

## 📋 Общее описание проекта

**Название:** Linap2 - CS2 Video Platform  
**Тип:** Веб-приложение для хранения и просмотра видеоклипов игроков Counter-Strike 2  
**Язык интерфейса:** Русский  
**Архитектура:** Монолитная (Frontend + Backend)  

### Назначение
Linap2 - это платформа для кланов и игроков Counter-Strike 2, позволяющая:
- Загружать видеоклипы с прецедентами (моменты на атаке/обороне)
- Каталогизировать видео по агентам и тактикам
- Обмениваться тактическими знаниями через видео
- Анализировать и комментировать игровые моменты
- Ранжировать контент через лайки и дислайки

---

## 👥 Акторы (Действующие лица)

### Основной актор
- **Пользователь (User)** - Зарегистрированный игрок/член команды

### Системный актор
- **Система (System)** - Автоматические процессы (статистика, индексирование, уведомления)

## 🎯 Основные прецеденты (Use Cases)

### 1. АУТЕНТИФИКАЦИЯ И ДОСТУП

#### UC1: Регистрация нового пользователя
**Предусловие:** Пользователь не зарегистрирован  
**Основной поток:**
1. Пользователь заполняет форму (username, email, пароль, отображаемое имя)
2. Система валидирует уникальность username и email
3. Система хеширует пароль (bcrypt)
4. Система создает запись User в БД
5. Система отправляет письмо верификации на email
6. Пользователь подтверждает email
**Постусловие:** Пользователь создан, может войти в систему

#### UC2: Вход в систему (Login)
**Предусловие:** Пользователь зарегистрирован  
**Основной поток:**
1. Пользователь вводит username/email и пароль
2. Система проверяет существование пользователя
3. Система проверяет пароль (bcrypt.verify)
4. Система генерирует JWT токен (HS256)
5. Система сохраняет сессию в БД
6. Система возвращает access_token
7. Frontend сохраняет токен в localStorage
8. Система загружает профиль пользователя
**Постусловие:** Пользователь авторизирован, видит свой профиль

#### UC3: Выход из системы (Logout)
**Основной поток:**
1. Пользователь нажимает "Выход"
2. Frontend удаляет токен из localStorage
3. Backend удаляет сессию из БД
4. Пользователь возвращается на главную
**Постусловие:** Сессия завершена, требуется повторный вход

#### UC4: Восстановление пароля
**Основной поток:**
1. Пользователь вводит email на странице "Забыли пароль"
2. Система проверяет наличие пользователя
3. Система генерирует токен восстановления
4. Система отправляет ссылку на email
5. Пользователь переходит по ссылке
6. Пользователь вводит новый пароль
7. Система обновляет пароль (hashed)
**Постусловие:** Пароль изменен, пользователь может войти с новым паролем

### 2. УПРАВЛЕНИЕ ПРОФИЛЕМ

#### UC5: Просмотр профиля
**Основной поток:**
1. Пользователь открывает свой профиль
2. Система загружает данные User (username, avatar, display_name)
3. Система загружает список загруженных видео пользователя
4. Система рендерит видео карточки
**Постусловие:** Пользователь видит свой профиль с видео

#### UC6: Изменить отображаемое имя (display name)
**Основной поток:**
1. Пользователь открывает модальное окно "Настройки"
2. Пользователь вводит новое display_name
3. Система валидирует (не пусто, макс 100 символов)
4. Система отправляет PUT /users/{user_id}
5. Система обновляет display_name в БД
6. Пользователь видит обновленное имя
**Постусловие:** Display name изменено

#### UC7: Загрузить или изменить аватар
**Основной поток:**
1. Пользователь выбирает файл аватара (JPG/PNG)
2. Frontend валидирует размер и формат
3. Frontend создает FormData с файлом
4. Frontend отправляет POST /users/{user_id}/avatar
5. Backend сохраняет файл в uploads/avatars/
6. Backend обновляет avatar_url в БД
7. Frontend обновляет аватар на странице
**Постусловие:** Новый аватар установлен

#### UC8: Изменить пароль
**Основной поток:**
1. Пользователь вводит старый пароль
2. Пользователь вводит новый пароль (мин. 8 символов)
3. Система проверяет старый пароль
4. Система хеширует новый пароль
5. Система обновляет hashed_password в БД
**Постусловие:** Пароль изменен успешно

### 3. ЗАГРУЗКА И УПРАВЛЕНИЕ ВИДЕО

#### UC9: Загрузить видео
**Предусловие:** Пользователь авторизирован  
**Основной поток:**
1. Пользователь нажимает кнопку "Загрузить видео"
2. Система показывает форму загрузки с полями:
   - title: строка (макс 255 символов)
   - description: текст (макс 2000 символов)
   - agent: выбор из списка агентов CS2
   - side: выбор (Attack/Defense)
   - file: видеофайл (MP4, MOV, макс 500 МБ)
3. Пользователь заполняет форму
4. Пользователь выбирает видеофайл
5. Frontend валидирует форму
6. Frontend создает FormData
7. Frontend отправляет POST /videos/upload + Bearer token
8. Frontend показывает прогресс загрузки (XHR progress)
9. Backend проверяет JWT токен
10. Backend валидирует параметры (расширение, размер)
11. Backend генерирует уникальное имя файла (timestamp + UUID)
12. Backend сохраняет файл асинхронно в uploads/videos/ (aiofiles)
13. Backend создает запись Video в БД с owner_id
14. Backend возвращает video_url + metadata
15. Frontend обновляет список видео профиля
16. Пользователь видит загруженное видео
**Исключение - неправильный формат:** Backend возвращает 422, Frontend показывает ошибку  
**Исключение - недостаточно прав:** Backend возвращает 403  
**Постусловие:** Видео загружено и доступно для просмотра

#### UC10: Просмотреть видео
**Основной поток:**
1. Пользователь открывает главную страницу или профиль
2. Система загружает GET /videos (или /users/{id}/videos)
3. Backend возвращает массив Video объектов (отсортированных по created_at DESC)
4. Frontend рендерит видео карточки с:
   - thumbnail
   - title
   - description (первая строка)
   - автор (owner.username)
   - агент, тактика (agent, side)
   - счетчики (views, likes, dislikes)
   - дата загрузки
5. Пользователь видит карточки видео с кнопкой ▶️
6. Пользователь кликает на карточку
7. Frontend вызывает openVideoPlayer(video)
8. Frontend устанавливает src видео в HTML5 <video> элемент
9. Frontend показывает modal окно videoPlayerModal
10. Frontend автоматически запускает воспроизведение (play())
11. Пользователь видит видео в плеере с нативными контролами
12. Система увеличивает счетчик views на 1
13. Пользователь может паузировать, менять громкость, развернуть на полный экран
**Постусловие:** Видео воспроизводится, просмотр записан

#### UC11: Удалить видео
**Предусловие:** Пользователь - владелец видео  
**Основной поток:**
1. Пользователь открывает свой профиль
2. Пользователь видит свои видео с кнопкой "удалить"
3. Пользователь нажимает кнопку удаления
4. Система показывает подтверждение
5. Пользователь подтверждает
6. Frontend отправляет DELETE /videos/{video_id}
7. Backend проверяет владельца (owner_id == user_id)
8. Backend удаляет файл из uploads/videos/
9. Backend удаляет запись из БД (вместе с likes/dislikes/comments)
10. Frontend обновляет список видео
**Исключение - не владелец:** Backend возвращает 403  
**Постусловие:** Видео и файл удалены

#### UC12: Отредактировать видео (метаданные)
**Предусловие:** Пользователь - владелец видео  
**Основной поток:**
1. Пользователь нажимает "редактировать" на карточке видео
2. Система показывает форму с текущими значениями
3. Пользователь изменяет title, description, agent, side
4. Frontend отправляет PUT /videos/{video_id}
5. Backend проверяет владельца
6. Backend обновляет поля в БД
7. Frontend обновляет карточку видео
**Исключение - не владелец:** Backend возвращает 403  
**Постусловие:** Метаданные видео обновлены

---

### 4. ВЗАИМОДЕЙСТВИЕ С ВИДЕО (СОЦИАЛЬНЫЕ ФУНКЦИИ)

#### UC13: Лайкнуть видео
**Основной поток:**
1. Пользователь смотрит видео в плеере
2. Пользователь кликает кнопку "👍 Нравится"
3. Frontend отправляет POST /videos/{video_id}/like + Bearer token
4. Backend проверяет JWT токен
5. Backend проверяет, лайкал ли пользователь это видео (в таблице likes)
6. **Если да (уже лайкал):**
   - Backend удаляет запись из таблицы likes
   - Backend уменьшает likes на 1 в videos
   - Backend возвращает {message: 'Like removed', likes: N}
7. **Если нет (первый раз лайкит):**
   - Backend вставляет запись в таблицу likes (video_id, user_id)
   - Backend увеличивает likes на 1 в videos
   - Backend возвращает {message: 'Like added', likes: N}
8. Frontend обновляет счетчик лайков на экране
9. Frontend визуально отмечает кнопку (например, меняет цвет)
**Постусловие:** Лайк добавлен/удален, счетчик обновлен

#### UC14: Дислайкнуть видео
**Основной поток:**
Аналогично UC13, но с таблицей dislikes и кнопкой "👎 Не нравится"
1. Пользователь кликает кнопку "👎 Не нравится"
2. Frontend отправляет POST /videos/{video_id}/dislike
3. Backend проверяет наличие в таблице dislikes
4. **Если уже дислайкал:** удаляет, уменьшает счетчик
5. **Если нет:** вставляет, увеличивает счетчик
6. Frontend обновляет счетчик дислайков
**Постусловие:** Дислайк добавлен/удален

#### UC15: Добавить комментарий к видео
**Основной поток:**
1. Пользователь смотрит видео в плеере
2. Пользователь видит раздел "Комментарии" под плеером
3. Пользователь вводит текст комментария
4. Пользователь нажимает "Отправить"
5. Frontend валидирует текст (не пусто, макс 1000 символов)
6. Frontend отправляет POST /comments
   - body: {video_id, content}
   - Authorization: Bearer token
7. Backend создает запись Comment (video_id, author_id, content, created_at)
8. Backend возвращает ID комментария
9. Frontend добавляет комментарий в список на странице
10. Пользователь видит свой комментарий
**Постусловие:** Комментарий добавлен, видна автору и другим

#### UC16: Удалить комментарий
**Предусловие:** Пользователь - автор комментария  
**Основной поток:**
1. Пользователь видит свой комментарий с кнопкой "удалить"
2. Пользователь нажимает кнопку
3. Frontend отправляет DELETE /comments/{comment_id}
4. Backend проверяет author_id == user_id
5. Backend удаляет запись из БД
6. Frontend удаляет комментарий с экрана
**Исключение - не автор:** Backend возвращает 403  
**Постусловие:** Комментарий удален

### 5. ПОИСК И ФИЛЬТРАЦИЯ

#### UC17: Фильтровать видео
**Основной поток:**
1. Пользователь видит панель фильтров (chips/tags):
   - По агенту (Raze, Phoenix, Sage, и т.д.)
   - По тактике (Attack, Defense)
   - По автору
2. Пользователь выбирает фильтры
3. Frontend отправляет GET /videos?agent=X&side=Y&author=Z
4. Backend фильтрует видео по параметрам
5. Backend возвращает отфильтрованный массив
6. Frontend обновляет сетку видео
7. Пользователь видит только видео, соответствующие фильтрам
**Постусловие:** Видео отфильтрованы

#### UC18: Поиск видео
**Основной поток:**
1. Пользователь вводит текст в поле поиска
2. Frontend отправляет GET /videos/search?q=текст
3. Backend ищет в title, description, автора, тегах
4. Backend возвращает список результатов
5. Frontend показывает результаты поиска
**Постусловие:** Результаты поиска отображены

---

### 6. СИСТЕМНЫЕ ОПЕРАЦИИ

#### UC19: Получить уведомление
**Автор:** Система  
**Основной поток:**
1. Кто-то лайкнул видео пользователя
   - ИЛИ: добавил комментарий к видео
   - ИЛИ: подписался на пользователя
2. Система создает запись Notification
3. Система отправляет WebSocket событие (или polling)
4. Frontend показывает всплывающее уведомление
**Постусловие:** Пользователь получил уведомление

#### UC20: Сохранить видео файл на сервер
**Триггер:** UC9 (Загрузить видео)  
**Основной поток:**
1. Backend получает файл в формате multipart/form-data
2. Backend валидирует MIME type (video/mp4, video/quicktime)
3. Backend генерирует уникальное имя: {timestamp}_{uuid}.mp4
4. Backend асинхронно сохраняет в uploads/videos/ (aiofiles)
5. Backend возвращает путь файла
**Постусловие:** Файл сохранен на диск, доступен для скачивания/streaming

#### UC21: Обновить статистику видео
**Триггер:** Различные действия (просмотр, лайк, комментарий)  
**Основной поток:**
1. Система отслеживает события:
   - Просмотр: views += 1
   - Лайк: likes += 1 (или -= 1 при удалении)
   - Дислайк: dislikes += 1 (или -= 1)
   - Комментарий: comments += 1
2. Система обновляет счетчики в таблице videos
3. Система использует эти данные для сортировки (популярность)
**Постусловие:** Статистика актуальна

#### UC22: Верифицировать JWT токен
**Триггер:** Каждый защищенный запрос  
**Основной поток:**
1. Frontend отправляет заголовок Authorization: Bearer {token}
2. Backend функция get_current_user() обрабатывает запрос
3. Backend извлекает токен из заголовка
4. Backend проверяет наличие "Bearer " префикса
5. Backend декодирует JWT (jose.jwt.decode)
6. Backend проверяет подпись (SECRET_KEY)
7. Backend проверяет время жизни (exp < now)
8. Backend извлекает user_id и username из payload
9. Backend возвращает TokenData объект
**Исключение - невалидная подпись:** HTTPException 401  
**Исключение - истек токен:** HTTPException 401  
**Постусловие:** Токен верифицирован, текущий пользователь определен

## 🔐 Требования безопасности и ограничения

### Аутентификация
- Только зарегистрированные пользователи могут загружать видео
- Каждый запрос требует валидный JWT токен
- Пароли хешируются bcrypt (не сохраняются в открытом виде)

### Авторизация
- Пользователь может редактировать/удалять только свои видео и комментарии
- Все остальные могут только просматривать и лайкать/комментировать

### Валидация файлов
- Только MP4 и MOV форматы (проверка MIME type)
- Максимум 500 МБ на файл
- Имя файла генерируется сервером (безопасность)

### Валидация данных
- Username: 3-50 символов, буквы/цифры/_
- Email: валидный формат
- Password: мин. 8 символов
- Display name: макс 100 символов
- Video title: макс 255 символов
- Video description: макс 2000 символов
- Comment: макс 1000 символов

### Rate limiting (опционально)
- Макс 5 загрузок видео в час на пользователя
- Макс 10 комментариев в минуту
